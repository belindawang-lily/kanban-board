# 投资管理训练营 · 运营进度看板

面向训练营运营的进度看板系统，覆盖 **总看板 / 队伍管理 / OKR / 双周报 / 日常打卡 / 一键快报** 六大模块。

数据源：飞书多维表格。看板为**静态快照**——飞书数据更新后需运行同步脚本刷新。

---

## 一、系统架构与限制

### 工作原理

```
飞书多维表格（数据源）  →  同步脚本  →  data.js（静态快照）  →  HTML 看板（展示）
```

- 看板是纯 HTML + CSS + JS，双击即用，可离线查看
- `data.js` 是飞书数据的**静态快照**，不是实时读取
- 飞书中数据变动后，管理员需手动运行同步脚本刷新 `data.js`
- 所有"新建/编辑/填报"按钮跳转到飞书 Base 对应表，在飞书中操作

### 已知限制

1. **数据非实时**：飞书更新后需手动运行 `node scripts/sync-via-lark-cli.mjs`，再刷新浏览器
2. **无看板级权限控制**：看板中所有按钮对所有用户可见（实际数据编辑在飞书 Base 侧控制）
3. **飞书 Base 权限**：已创建 12 个团队角色并配置行级权限（`is_invalid=false`，已验证生效）。角色按「所属团队」字段过滤，每个团队只能编辑本团队记录。管理员需在飞书界面手动将成员分配到对应角色

## 二、快速上手

### 看数据（任何人）

双击 `index.html`，浏览器打开即可。

### 填报数据（所有队员）

点击看板中的「新建目标」「填报新一期」「新增打卡」等按钮 → 跳转到飞书多维表格对应表 → 在飞书中操作。

飞书 Base 地址：`https://qcnjj22jqvr1.feishu.cn/base/NVokbNXaca3oihspnCicYyccnVe`

### 刷新看板（管理员）

飞书中有数据更新后：

```bash
cd kanban-board
node scripts/sync-via-lark-cli.mjs
```

然后刷新浏览器（Ctrl+F5）。前提：本机已安装并登录 lark-cli（`lark-cli auth status` 可查看状态）。

### 更好的做法（可选）

如果希望自动刷新，可选：
- **定时同步**：用操作系统定时任务每隔 N 分钟运行一次同步脚本
- **轻量服务器**：用 Node.js 起一个简单 HTTP 服务，每次请求时从飞书拉取最新数据（替代静态 data.js）
- **飞书自动化**：在飞书 Base 中配置「工作流」触发器，数据变更时调用 webhook 通知管理员

## 三、功能清单

### 总看板（index.html）

- 6 项核心指标（一行展示）：队伍数、成员数、OKR 平均进度、本期双周报提交率、打卡活动数、有风险 KR 数
- 各队 OKR 进度总览表：队伍、队长、成员、进度条、KR 数、最新双周报、打卡数、状态
- 点击队伍行跳转 OKR 详情页
- 打卡活跃度 Top 6 横向条形图
- 本期双周报提交情况表（含提交率进度条）
- 身份参与统计表（成员/志愿者/内部导师/外部导师）

### 队伍管理（team-management.html）

- 左侧队伍列表（含进度条），右侧队伍详情
- 队伍详情：队长、周期、成员数、打卡数
- 成员名册：姓名、身份、角色、OA 号、累计参与次数（含迷你条形图）
- 身份分布卡（人数 + 占比 + 参与人次）
- 导出成员名单 CSV
- 「新建队伍」「添加成员」「编辑信息」「解散队伍」按钮 → 跳转飞书 Base 操作

### OKR 管理（okr.html）

- 全部队伍 OKR 总览（支持 ?team=队伍ID 查看单队）
- OKR 树形展示：目标（O）→ 关键结果（KR）层级
- KR 进度条 + 状态标签（未开始/进行中/已完成/有风险）
- KR 状态分布统计

### 双周报（biweekly-report.html）

- 全部队伍总览（支持 ?team=队伍ID 查看单队）
- 双周报时间线展示
- 每期报告：报告标题、周期、记录人、本期进展、问题与需求
- 关联 KR 更新展示
- 「填报新一期」按钮 → 跳转飞书 Base

### 日常打卡（checkin.html）

- 全部队伍概览（支持 ?team=队伍ID 查看单队）
- 打卡时间线：活动时间、研讨内容、打卡照片、参与人头像组
- 身份参与统计（柱状图）
- 导出打卡统计 CSV（按队伍汇总 / 按人明细）
- 「新增打卡」按钮 → 跳转飞书 Base

### 项目快报（quick-brief.html）

- 一键生成整体快报或单队快报（下拉选择队伍）
- 快报内容：整体概览 → OKR 进度排名 → 双周报亮点摘录 → 打卡统计 → 风险预警 → 任务完成率 → 下阶段重点
- 导出 PDF（浏览器打印功能）

## 六、同步脚本

```bash
node scripts/sync-via-lark-cli.mjs
```

从飞书 Base 拉取 6 张表数据，映射为看板格式，写入 `assets/js/data.js`。

- 前提：本机已安装 lark-cli 并登录
- 团队归属：通过「所属团队」单选字段匹配队伍表记录
- 进度格式：飞书百分比（小数 0.65）自动归一化为 0-100 整数

## 七、日常使用流程

### 首次部署

1. 安装 Node.js 18+
2. 安装并登录 lark-cli
3. 运行 `node scripts/sync-via-lark-cli.mjs` 生成 data.js
4. 双击 `index.html` 打开看板

### 日常操作

1. 队员在飞书 Base 中填报数据（双周报、打卡、更新 KR 进度等）
2. 管理员运行同步脚本刷新看板
3. 刷新浏览器查看最新数据

### 导出数据

- 成员名单：队伍管理页 → 导出名单（CSV）
- 打卡统计：日常打卡页 → 导出统计（CSV，按队伍/按人）
- 项目快报：项目快报页 → 导出 PDF（浏览器打印）

## 八、技术说明

- 零外部依赖：纯 HTML + CSS + 原生 JS
- 数据内嵌：`data.js` 以 `window.KANBAN_DATA` 变量内嵌，避免 `file://` 跨域问题
- 同步脚本：Node 18+，无需安装 npm 包
- CSV 导出：浏览器直接下载，带 BOM 头确保中文兼容
- 所有编辑操作通过跳转飞书 Base 实现，数据在飞书侧持久化

## 九、飞书 Base 权限配置

### 已配置内容

12 个自定义角色（团队1编辑 ~ 团队12编辑），每个角色的权限规则：

| 表 | 权限 | 可编辑范围 | 可阅读范围 |
|----|------|-----------|-----------|
| 成员 | 可编辑 | 所属团队 = 本团队 | 所有记录 |
| 目标 | 可编辑 | 所属团队 = 本团队 | 所有记录 |
| 关键结果 | 可编辑 | 所属团队 = 本团队 | 所有记录 |
| 双周报 | 可编辑 | 所属团队 = 本团队 | 所有记录 |
| 打卡 | 可编辑 | 所属团队 = 本团队 | 所有记录 |
| 队伍 | 只读 | — | 所有记录 |

高级权限已开启。分享对话框中会显示"高级权限已开启，用户的权限同时受到角色设定限制"。

### 分配成员到角色（管理员手动操作）

CLI 不支持角色成员分配，需在飞书界面操作：

1. 打开 Base → 点击右上角蓝色「分享」按钮
2. 在弹出的分享对话框中，搜索并邀请协作者
3. 邀请后，点击协作者名字旁的下拉框，选择对应的团队角色（如"团队1编辑"）
4. 重复以上步骤，把每个团队成员分配到对应角色

### 验证权限生效

分配完成后，用被分配的账号打开 Base，确认：
- 能看到所有团队的记录（只读）
- 只能编辑本团队的记录（其他团队的记录编辑按钮灰色或不可点击）
- 队伍表为只读
