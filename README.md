# 澎π计划AI训练营 · 运营进度看板

面向训练营运营的进度看板系统，覆盖 **总看板 / 队伍管理 / OKR / 双周报 / 日常打卡 / 一键快报** 六大模块。

数据源：飞书多维表格。GitHub Actions 每天自动同步数据并部署到公网。

**公网访问地址**：`https://belindawang-lily.github.io/kanban-board/`

---

## 一、系统架构

### 工作原理

```
飞书多维表格（数据源）  →  GitHub Actions 自动同步（每天2次）  →  data.js  →  GitHub Pages 公网展示
```

- 队员在飞书 Base 中填报数据
- GitHub Actions 每天 8:00 / 20:00（北京时间）自动拉取飞书数据并部署
- 看板支持公网访问，领导无需安装任何软件，浏览器打开链接即可
- 所有"新建/编辑/填报"按钮跳转到飞书 Base 对应表，在飞书中操作

### 手动同步（可选）

如需立即刷新数据，在 GitHub Actions 页面手动触发 `Sync & Deploy` workflow 即可。

也可本地运行（需设置环境变量 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`）：

```bash
node scripts/sync-feishu-api.mjs
```

### 已知限制

1. **数据有延迟**：飞书更新后最长等 12 小时自动同步，或手动触发 workflow 立即同步
2. **无看板级权限控制**：看板中所有按钮对所有用户可见（实际数据编辑在飞书 Base 侧控制）
3. **飞书 Base 权限**：已创建 12 个团队角色并配置行级权限。管理员需在飞书界面将成员分配到对应角色

## 三、功能清单

### 总看板（index.html）

- 6 项核心指标（一行展示）：队伍数、成员数、OKR 平均进度、本期双周报提交率、打卡活动数、有风险 KR 数
- 各队 OKR 进度总览表：队伍、队长、成员、进度条、KR 数、最新双周报、打卡数、状态
- 点击队伍行跳转 OKR 详情页
- 打卡活跃度 Top 6 横向条形图
- 本期双周报提交情况表（含提交率进度条）
- 身份参与统计表（成员/志愿者/内部导师/外部导师）

### 队伍管理（team-management.html）

- 左侧队伍列表（含进度条），右侧队伍详情
- 队伍详情：队长、周期、成员数、打卡数
- 成员名册：姓名、身份、角色、OA 号、累计参与次数（含迷你条形图）
- 身份分布卡（人数 + 占比 + 参与人次）
- 导出成员名单 CSV
- 「新建队伍」「添加成员」「编辑信息」「解散队伍」按钮 → 跳转飞书 Base 操作

### OKR 管理（okr.html）

- 全部队伍 OKR 总览（支持 ?team=队伍ID 查看单队）
- OKR 树形展示：目标（O）→ 关键结果（KR）层级
- KR 进度条 + 状态标签（未开始/进行中/已完成/有风险）
- KR 状态分布统计

### 双周报（biweekly-report.html）

- 全部队伍总览（支持 ?team=队伍ID 查看单队）
- 双周报时间线展示
- 每期报告：报告标题、周期、记录人、本期进展、问题与需求
- 关联 KR 更新展示
- 「填报新一期」按钮 → 跳转飞书 Base

### 日常打卡（checkin.html）

- 全部队伍概览（支持 ?team=队伍ID 查看单队）
- 打卡时间线：活动时间、研讨内容、打卡照片、参与人头像组
- 身份参与统计（柱状图）
- 导出打卡统计 CSV（按队伍汇总 / 按人明细）
- 「新增打卡」按钮 → 跳转飞书 Base

### 项目快报（quick-brief.html）

- 一键生成整体快报或单队快报（下拉选择队伍）
- 快报内容：整体概览 → OKR 进度排名 → 双周报亮点摘录 → 打卡统计 → 风险预警 → 任务完成率 → 下阶段重点
- 导出 PDF（浏览器打印功能）

## 六、同步机制

### 自动同步（GitHub Actions）

`.github/workflows/sync-and-deploy.yml` 配置了定时任务：

- 每天 08:00 和 20:00（北京时间）自动从飞书拉取数据，写入 `data.js` 并部署到 GitHub Pages
- 也可在 GitHub Actions 页面手动触发 `Sync & Deploy` workflow
- 依赖 GitHub Secrets：`FEISHU_APP_ID`、`FEISHU_APP_SECRET`

### 本地手动同步

```bash
# 方式1：飞书 API（需设置环境变量 FEISHU_APP_ID / FEISHU_APP_SECRET）
node scripts/sync-feishu-api.mjs

# 方式2：lark-cli（需本机已登录 lark-cli）
node scripts/sync-via-lark-cli.mjs
```

团队归属通过「所属团队」单选字段匹配；进度格式自动归一化为 0-100 整数。

## 七、日常使用流程

### 首次部署

已完成：
1. 飞书 Base 创建 + 数据导入 + 权限配置
2. 飞书自建应用创建 + 发布 + API 权限开通
3. GitHub 仓库创建 + 代码推送 + Secrets 配置 + Pages 启用

1. 队员在飞书 Base 中填报数据（双周报、打卡、更新 KR 进度等）

### 导出数据

- 成员名单：队伍管理页 → 导出名单（CSV）
- 打卡统计：日常打卡页 → 导出统计（CSV，按队伍/按人）

## 八、技术说明

- 零外部依赖：纯 HTML + CSS + 原生 JS
- 数据内嵌：`data.js` 以 `window.KANBAN_DATA` 变量内嵌，避免 `file://` 跨域问题
- 同步脚本：Node 18+，无需安装 npm 包
- CSV 导出：浏览器直接下载，带 BOM 头确保中文兼容
- 所有编辑操作通过跳转飞书 Base 实现，数据在飞书侧持久化

## 九、飞书 Base 权限配置

### 已配置内容

12 个自定义角色（团队1编辑 ~ 团队12编辑），每个角色的权限规则：

| 表 | 权限 | 可编辑范围 | 可阅读范围 |
|----|------|-----------|-----------|
| 成员 | 可编辑 | 所属团队 = 本团队 | 所有记录 |
| 目标 | 可编辑 | 所属团队 = 本团队 | 所有记录 |
| 关键结果 | 可编辑 | 所属团队 = 本团队 | 所有记录 |
| 双周报 | 可编辑 | 所属团队 = 本团队 | 所有记录 |
| 打卡 | 可编辑 | 所属团队 = 本团队 | 所有记录 |
| 队伍 | 只读 | — | 所有记录 |

高级权限已开启。分享对话框中会显示"高级权限已开启，用户的权限同时受到角色设定限制"。

### 分配成员到角色（管理员手动操作）

CLI 不支持角色成员分配，需在飞书界面操作：

1. 打开 Base → 点击右上角蓝色「分享」按钮
2. 在弹出的分享对话框中，搜索并邀请协作者
3. 邀请后，点击协作者名字旁的下拉框，选择对应的团队角色（如"团队1编辑"）
4. 重复以上步骤，把每个团队成员分配到对应角色

### 验证权限生效

分配完成后，用被分配的账号打开 Base，确认：
- 能看到所有团队的记录（只读）
- 只能编辑本团队的记录（其他团队的记录编辑按钮灰色或不可点击）
- 队伍表为只读
